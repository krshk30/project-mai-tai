## Disposition

AGREE with the operator-approved process goal: preserve an immutable committed
independent review across a same-PR, unchanged-patch rebase; a superseded record
must not poison current coverage. Batch landing should report old/new hashes,
send changed patches back for review, and retain single-marker independence.

DISAGREE that SHA256 of ONLY +/- diff lines is sufficient authorization. It is
a useful diagnostic fingerprint, not complete change identity or a proof of
semantic equivalence on another base. File metadata, binary content, newline
state, source provenance, current authorship and current integration still
matter. The proposal needs an explicit versioned canonicalization/eligibility
contract; silently excluding those effects would widen the review gate.

UNMEASURED: implementation correctness, adversarial controls, CI/merge-race
handling, batch-landing behavior and behavioral equivalence after base changes.
The tests below are proposed, NOT executed. No new pin coverage is asserted.

## Concrete Failure Cases And Required Design

| Case | Why raw +/- hash is insufficient | Proposed treatment |
| --- | --- | --- |
| Paths | Same payload in gates.py versus tests/gates.py; +++/--- retention helps but empty files/pure renames have no such content headers | Bind raw old/new repository paths and operation in a deterministic file manifest; use unambiguous length/NUL framing, not whitespace tokenization |
| Mode/type | chmod100644->100755 produces no +/- lines; regular text file and symlink can contain the same +target bytes | Bind old/new Git modes/types, including120000symlink/160000gitlink; unsupported types stop |
| Binary | Two entirely different binary replacements normally have no +/- payload; filtering both gives the empty digest | Include exact pre/post binary blob content SHA256 or explicitly refuse binary eligibility; never classify empty fingerprint as reviewed |
| Empty files | Adding/deleting a zero-byte file can change behavior without a content hunk | Bind creation/deletion paths and modes even when there are no text lines |
| Whitespace | Python indentation, tabs, quoted spaces and Make recipes are behavior; strip()/whitespace normalization can collide | Preserve exact changed payload bytes, leading/trailing whitespace and CR; normalize only defined Git presentation fields |
| EOF newline | +x with/without the '\\ No newline at end of file' marker has equal filtered lines but different blobs | Bind relevant pre/post EOF-newline state/marker; do not silently drop it |
| Context/site | Identical '-return True/+return False' at allowed() versus denied() can have the same lines even with path headers | Not semantic equivalence; relocation/ambiguity and affected-context changes need explicit review/eligibility policy |
| Changed base | Unchanged local patch can behave differently when caller defaults, mixins, imports or invariants change | Retain base/head provenance, report touched/context/dependency base changes, fresh integration checks and human landing authority; never claim hash proves behavioral equivalence |
| Attributes/drivers | Attributes or textconv/external diff can hide/transform changed bytes | Fixed trusted diff options, no external/textconv execution, classify actual file effects independently; never execute untrusted PR configuration |
| Marker/self-review | Rewritten messages can drop/swap owners while keeping exactly the same tree/patch | Revalidate every current PR-range commit's single canonical marker against the matching reviewer's identity; do not rely only on old authorship |
| Dirty ledger | Edited working-copy patch_sha256 can appear to have one historical ledger commit | Read exact regular-file JSON blobs from a pinned ledger tree, verify record commit provenance/immutability; untracked/staged/unstaged/symlink inputs cannot authorize |
| Wrong PR/schema | Equal content elsewhere is not a review of this PR | Bind repository, PR number, algorithm/schema version and reviewer; another PR/unknown schema cannot authorize |

Hash framing must retain file/block order and exact payload boundaries. Blindly
sorting +/- lines or joining them without delimiters loses operation identity.
Select whole-PR base..head changes deterministically, never 'only the last commit'
or a source-only subset. The original base/head stay recorded as provenance;
'base-independent' means the hash does not contain their OIDs, not that the
review's assumptions or trust no longer depend on its original base.
