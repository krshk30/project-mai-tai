## Tick-Path Review Follow-Up

The review blocker on 16c435b0 was reproduced by code inspection: every tick
opened a session while any hold existed, before matching the symbol, and copied
the entire map. This follow-up removes that behavior without changing pricing.

- Tick admission is in-memory only: matching held symbol, fresh executable ask,
  trigger/cap evaluation. Unrelated and stale ticks never open a session, read
  ownership, or copy a hold. Only an eligible transition copies its own hold.
- Reason/fill/existing-order reads use the periodic `symbol=None` turn, off-loop
  through `_run_db`, at the existing broker-sync cadence (5 seconds by default).
- Eligible persistence uses `_run_db` with a durable compare-and-set on row,
  phase, token, intent and event. Workers return results; only the loop updates
  the runtime map. Cancellation/replacement during a pending write cannot
  resurrect a retired hold. Concurrent ticks share an in-memory per-slot fence.
- The serial pre-wire claim still repeats ownership and price proof. Removing
  tick-time ownership queries does not authorize a buy from stale periodic proof.
