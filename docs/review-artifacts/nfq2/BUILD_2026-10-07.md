## Pricing Before and After

| Path | Before | After |
| --- | --- | --- |
| Fresh reactive | Configured default 1.0% cap | Default 0.5% cap |
| Fresh software-rest | 0.5% band | Unchanged 0.5% band |
| Serially proven NFQ2 held entry, either path | Dropped when no fresh ask | 1.0% cap; ask above cap gives up |
| Reactive limit buffer | Ask +0.3%, bounded by cap | Unchanged |
| NFQ1 RTH resting mirror / ORB | Existing pricing and holds | Unchanged |
| Legacy mirror-on-fill | Shared reactive max-cross setting, default 1.0% | Separate `oms_v2_mirror_eh_max_cross_pct`, default 1.0% |

The mirror-on-fill setting split preserves that third producer's default rather
than tightening it accidentally. A deployment must inspect any existing custom
override and retain its old mirror-on-fill value under the new key. The fresh
reactive default change takes effect even with NFQ2 OFF; it is the explicitly
approved pricing change, not an inert-off claim.

Freshness is <=10,000 ms with NFQ2 ON. The serial hold token, durable hold ID,
account, slot and segment must agree before the held band is trusted. Incoming
metadata alone cannot claim held pricing. NFQ2 OFF retains the old quote ages.

give-up therefore release that exact attempt, not a predecessor's latch.

## Remaining Review Proofs

This draft is NOT ready for pin. In particular:

- An uncertain wire dispatch stays blocking; this patch does not automatically
  release it on a later terminal-cancel proof. A reviewed reconciliation path
  is needed before claiming recovery complete.
- New producers carry account/slot/segment identities with NFQ2 ON. Legacy
  unbound entries still go to the existing visible refusal, not a durable hold;
  activation needs a proven drain or safe identity policy for those entries.
- Feedback tests cover wrong slot/segment, own fill and retry predecessor, but
  do not yet prove every cancel/replacement vs delayed feedback ordering or
  simultaneous v2/OMS restart. No such guarantee is claimed.
- Exact-tree NFQ2 + SLOTCLEAR1 composition and Linux CI are still required.

## Deployment Requirements (Not a GO)

Restart OMS and v2 in a reviewed coordinated install; no schema migration or
other service restart is required by this patch. Set
`MAI_TAI_OMS_V2_EH_FRESH_PRICE_ENABLED=true` on both, verify reactive cap 0.5,
preserve the legacy mirror cap, and verify the held-only band through the
serial claim. The standalone catalog has 149 boolean process checks +8 numeric
checks =157; this is an expectation, not a live PASS receipt.

Turning NFQ2 OFF stops creating new holds, but existing durable obligations
remain fail-closed and must not be discarded. Rollback/recovery needs separate
authorization. No merge, pin, install, production mutation or restart is done
in this side conversation.
