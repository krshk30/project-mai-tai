## Code and scope

- `_reset_atr_indicator_state` is called at **initial detection** in
  `begin_gap_hold`, and at a **second recovery gap** in `_prepare_gap_hold_bar`.
  `_maybe_resume_gap_hold` itself only releases after `2 * period` clean bars.
  Fixing only a presumed resume reset would leave the initial loss intact.
- `_queue_line_source_event` has a one-shot budget keyed to symbol, epoch,
  membership and reason. Multiple `gap_resume` events in the same membership
  need distinct hold identities, without changing the re-add/start budgets.

  use bounded `wait_for(to_thread(...), 6s)`; line math uses
  `wait_for(to_thread(...), 3s)`. No tick repair is necessary. New enqueue cost
  and new-path tick benchmark are **UNMEASURED**, since the build is stopped.
- The repair publishes ATR mathematics and confirmation-bar states together.
  Exit rules can remain unchanged, but their line inputs change; "every exit
  outcome unchanged" is not a valid blanket claim. Existing confirmation test
  demonstrates correction of a pending short reading to long without repeating
  an already-issued evaluation. No exit code is changed here.
